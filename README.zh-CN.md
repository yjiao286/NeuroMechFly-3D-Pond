# 🧠 NeuroMechFly-3D-Pond

**约 2.3k 行 Python 实现的 60 FPS 无引擎 3D 池塘**——自行完成投影、着色与光栅化，不用
OpenGL，除源码外不依赖任何美术/音频素材文件。池塘里有 9 个果蝇智能体，其中**恰好 1 个**由
泄漏整合发放（LIF）脉冲神经网络驱动（巨纤维逃逸、中央复合体转向、歇息回路控制进食）。
同一仓库还通过 MuJoCo 组装、仿真并渲染**真实的 NeuroMechFly** 身体模型——micro-CT 网格、
126 个转动自由度、复眼读数。

## 1 · 系统总览

仓库里是两套彼此独立的栈：A 栈是游戏本体——确定性仿真循环 + 手写软件光栅器；
B 栈是 FlyGym 桥接层——组装科学计算用的 MuJoCo 模型并离线渲染。两者除
`V3 = pygame.math.Vector3` 外不共享代码。

| 子系统 | 文件 | 行数 | 职责 |
|---|---|---|---|
| 主循环 / 智能体 / HUD | [`main.py`](main.py) | 817 | 60 FPS 定步长循环、青蛙运动学、两类果蝇、HUD、无头自测 |
| 软件渲染器 | [`render3d.py`](render3d.py) | 671 | `Camera3D` 透视投影、`Painter` 深度排序、生物精灵通道、材质图元 |
| 生物建模层 | [`models.py`](models.py) | 473 | 青蛙与果蝇的形体规格表、姿态函数、着色与脚趾/翅膜几何 |
| 神经智能体 | [`fly_brain.py`](fly_brain.py) | 155 | LIF 神经元、GF / CX / REST 环路、感觉整合、运动指令 |
| 场景 | [`scenery.py`](scenery.py) | 814 | 逐像素水面与焦散、涟漪、荷叶、食饵、岸景、布景、天空、按机位缓存 |
| 音频 | [`sounds.py`](sounds.py) | 127 | 22.05 kHz 程序化合成（蛙鸣/落水/咔嚓/振翅/吐舌） |
| FlyGym 桥 | [`real_fly_demo.py`](real_fly_demo.py) | 166 | 在 MuJoCo 中组装 NeuroMechFly，渲染本体与视网膜读数 |

运行期约定：窗口 1280 × 800（`SCALED │ RESIZABLE`），帧率上限 60 FPS，单步 dt 上限 1/20 s
（防卡顿后穿模），世界单位为池塘单位，所有随机布局均带固定种子。

## 2 · 脉冲神经智能体

`fly_brain.py` 实现 `dv/dt = (−(v − v_rest) + I)/τ` 的阈值复位动力学，为数值稳定按 τ/2
细分子步积分。默认参数 `v_rest = −70 mV`、`v_thr = −52 mV`、`v_reset = −76 mV`；发放即
`fired` 置位一帧，`activation ∈ [0,1]` 是归一化"距阈值距离"——也就是 `B` 面板里画的条。

| 环路 | 对应生物学结构 | τ | 驱动量 | 触发条件 |
|---|---|---|---|---|
| **GF** 巨纤维 | 逃逸反射 | 0.05 s | `55 · max(0, 1 − d_frog/260)`，跳跃时 ×3 | 威胁进入约 170 单位或头顶有跳跃阴影 → 0.85 s 逃逸推力 ×3.1，随后 1.6 s 不应期；对反复无害的静止威胁会**习惯化**（电流下限 ×0.45，贴脸约 70 单位仍逃），跳跃掠影立刻去习惯化 |
| **CX_L / CX_R** 中央复合体 | 航向控制 | 0.25 s | 两个慢振荡器竞争 | 以幅度差读出，产生平滑非周期的巡航 |
| **REST** 歇息/觉醒 | 进食闸门 | 0.6 s | 悬停且威胁 < 0.32 时 `45 · rest_fill` | 超阈值才释放降落动作；目标被占也照落——走近对峙，脚本个体会让位（领域性）；3.5 s 没吃到或歇满 9 s 主动起飞 |
| 气味趋向 | 趋化 | — | 朝最近食饵偏航 | 饥饿状态 |

其余 8 个智能体（`ScriptedFly`）是有限状态航点控制器：觅食 → 降落 → 啃食，110 单位内逃跑
（260 单位后解除）。神经元个体约 170 单位就逃——这就是"阈值检测器"与"脚本触发器"的可观测差异。

| | `ScriptedFly` | `BrainFly` |
|---|---|---|
| 决策来源 | 状态机 + 调参 | LIF 膜电位 |
| 逃逸触发 | 距离 < 110 | GF 越阈（初次约 170，习惯化后约 70） |
| 进食 | 计时器 | REST 闸门 |
| 可观测性 | 无 | `B` 面板逐神经元实时激活 |
| 池塘中数量 | 8 | 1（金色方框标注） |

## 3 · 渲染器

无 GPU、无深度缓冲。流水线为：世界坐标 → 视空间变换 → 近平面裁剪（Sutherland–Hodgman，
`NEAR = 14`）→ 透视投影（`focal = 1050 px`）→ 延迟提交给 painter → 逐层深度排序 → 光栅化。
多边形以闭包形式入队、由 `Painter.flush` 统一执行，这正是能做显式排序控制的原因。

| 层 | 内容 | 排序规则 |
|---|---|---|
| 0 `WATER` | 逐像素解析水面（反投影到 z=0 的一整张像） | 平面物，恒最先 |
| 1 `FX` | 岸边水线、涟漪、浮萍 | 只在水面之上 |
| 2 `PAD` | 预留给荷叶贴花 | — |
| 3 `BANK` | 堤壁、草地、卵石、岩石、灌木（缓存）、芦苇、草丛 | 深度排序，静态物按机位缓存 |
| 4 `MAIN` | 青蛙、果蝇、粒子、舌头 | 深度排序，最后绘制 |

**bias 约定（统一）。** 所有图元的 `bias` 都是 `depth - bias`：**正值 = 视觉上前置**。
早期 `limb()` / `segment()` 用的是 `depth + bias`（正值后置），两套相反的语义曾让"把前足压到
复眼之上"实际变成"把前足塞到复眼背后"——现在已统一，改图元排序时不必再记哪家是反的。

**为什么必须分层。** 用"多边形平均深度"把小型生物与大片地面一起排序，只要生物站在地面
多边形的远半侧就会被整片地面吞掉。拆成"纯平面恒垫底"与"立体物按深度排序"两层即可消除该
失效模式；同层的共面部件（叶面/叶脉/叶背、影子与本体）再用显式 `bias` 错开。

**生物精灵通道。** 青蛙与果蝇先画进各自的 3× 超采样画布（子相机就是把主相机的像平面
平移再放大），内部照常做深度排序，最后整体缩小贴回场景。轮廓因此自带抗锯齿，生物内部
不会与自身发生排序抖动，对外只占一个绘制项。

**渐进式抗锯齿。** 岸上静态布景只跟机位有关，因此缓存在一张贴图里：机位一停（约 6 帧）
就再用 2× 超采样重画一遍缩回来，整片沙滩/草地/灌木的轮廓都是平滑的；转动镜头时先用
1× 保证跟手。荷叶这类每帧都在动的形体则在填色后再沿同一条边描一圈抗锯齿线。水面同理，
静止时按 1/2 分辨率解析、转动时自动降到 1/3——肉眼看不出差别，转动时省一半时间。

**材质。** 全场景共用一盏世界空间主光（`LIGHT_XY`），镜头旋转时高光方向保持一致：

| 图元 | 用途 | 着色模型 |
|---|---|---|
| `sphere()` | 灌木、岩石、复眼、食饵、关节 | 边缘压暗 → 向光侧内缩提亮 → 镜面点 → 描边；小半径 LOD |
| `dome()` | 荷叶、卵石、翅面、高光带 | 边缘压暗 → 向光侧内缩高光 → 光泽 |
| `loft()` | 蛙体、果蝇胸腹 | 同一条轮廓按高度逐层收拢，叠出连续的曲面明暗 |
| `limb()` | 四肢、茎、翅脉 | 锥形胶囊多边形（两侧切线 + 端部半圆）+ 向光亮面 |
| `translucent_polys()` | 翅膜、趾间蹼 | 独立 SRCALPHA 面整体带 alpha 混合 |
| `soft_shadow()` | 所有落地物 | 预生成径向衰减贴图按投影椭圆缩放 |
| `flat_polygon()` / `segment()` / `polyline()` | 水面、叶脉、茎、舌头 | 平涂 + 深度偏置 |

实测开销：整池尽收眼底、机位静止时，无头软件渲染 **≈ 24 ms/帧**（1280 × 800 dummy SDL，
Python 3.14 + pygame-ce 2.5.8）；转动镜头时约 42 ms/帧，因为岸景缓存与水面都要重算。
水面图像每 3 帧重建一次（焦散本身是慢动作），静态岸景图层只在机位变化时重绘——
这两处缓存是主要的性能余量来源。

## 4 · 场景、建模与材质

![池塘中景：金色方框标注的神经元果蝇，右侧是 GF/CX/REST 神经面板](docs/images/pond-neural.png)

*整系统中景。画面里的东西全部由运行时代码生成——水体、带放射叶脉与翘边高光的荷叶、
湿沙到干沙的岸坡、芦苇与灌木。池塘中央就是**神经元个体**：金色方框标注它的当前状态
（`巡航`），右侧面板实时读出四条环路——青蛙已进入 170 单位逃逸半径，GF 正在充能；
CX_L / CX_R 是转向振荡器；REST 处于静默。*

所有几何在运行时由带种子的 RNG 生成，仓库内没有任何网格、贴图或音频文件。

| 元素 | 建模 | 贴图 / 着色 |
|---|---|---|
| 水面 | 池塘平面 ±620 × ±350，活动区 ±545 × ±285 | 每个像素反投影到 z=0 水面求世界坐标，再解析地算浅深、菲涅尔天空反射、扭曲正弦光网焦散与水线泡沫；静态部分按机位缓存 |
| 荷叶 | 6 片，半径 46–66，缺口 + 叶脉 + 可选荷花，按 `sin(1.2t + φ) · 1.6` 起伏 | 放射状渐细叶脉、近侧叶缘高光、叶背厚度、柔光接触影 |
| 青蛙 | 一体成型的躯干（沿体轴 30 层收拢）+ 折成 Z 字的四肢 + 程序化脚趾与趾间蹼 + 金环眼 | 背脊高光、迷彩斑、背侧褶、鼓膜、口裂、湿皮肤柔光、水面接触影 |
| 果蝇（`FLY_SCALE = 1.85` 整体放大，便于在池塘尺度下看清） | 砖红复眼（横向压扁的椭球）+ 额板与三个单眼 + 琥珀胸背/小盾片/黑刚毛 + 向后收细且下垂的带纹腹部 + 玻璃质半透明翅与翅脉 + 六足（髋-膝-跗）+ 平衡棒 | 逐部件着色、翅膜 alpha 混合、柔光阴影 |
| 岸景 | 4 面堤壁 × 8 段、44 单位岸顶、草地延伸至 2600 单位 | 湿沙→干沙渐变、卵石、岩石斑点、灌木簇、雾化草地、飘动云、地平线暖光 |

形体写在 [`models.py`](models.py) 的规格表里（半宽表、背高表、关节链），姿态函数按状态插值——
建模是"读数据 + 摆姿势"，不是一长串手调多边形。

**抢食机制。** 荷叶上的碎屑是稀缺资源（吃完 2.5~4 秒长回来），**同一时刻每块只容
1 只进食**（`FoodCrumb.CAPACITY = 1`），每片荷叶有两块碎屑（分居对侧）：

- 选食代价 = `距离 ÷ 空位数 × 个体偏好(0.8~1.2)`，余量新鲜的碎屑值得多飞一段路——
  空位多、更新鲜的更划算，个体偏好让同时选食的果蝇拆分到不同目标，不扎堆；
- 起飞去吃的路上会**预约座位**，规则是"**最近者得座**"：从自己到碎屑的距离数空位，
  只统计比自己更近的在途认领者——距离并排的两只不会互相把对方算成"占座的"，
  也就不会互相锁死在天上（容量=1 时踩过的坑：两只同时等位 → 各自都看到"满座" →
  谁也不敢落）。开吃由每块碎屑的**在座登记表**仲裁（帧首按进食状态重建、帧内
  实时增删），同帧先后落地的竞态也只有一个能入座；
- 目标满座时不硬挤：大圈缓飞等位（转弯率带个体微差，圈不重叠），快见底
  （余量 < 0.8）或等超过 3.5 秒就放弃、游荡片刻再选——"等位"只是短暂的争抢瞬间；
- **神经元个体有领域性**：它落定的荷叶就是它的领域，对峙有全套动作——不在同一块
  食饵上时先快步逼近，贴近后以 ~1 次/秒的节奏大幅**冲撞**（高抬前身、双前足向
  对手头顶猛探，真实果蝇攻击行为的标志性动作），翅膀同步半展做**展翅威胁**；
  正在进食的脚本个体则伏低、颤抖、抱着饭碗节节后退，撑不过 ~1.8 秒（挨上两记
  冲撞）就弃食让座，而且攻击方会直接改打"你的碗"——赢下后立刻吃掉战利品。
  实测 4 分钟 5~12 次逼退让位、它自己 26~32 餐（不少于任何一只脚本个体）；
  它的优势不在"吃得多"，而在"打得赢 + 胆子大"——对静止的青蛙习惯化后，
  敢落在玩家眼皮底下从容进食；
- 逃跑时立刻放弃认领，把座位让出来；神经元个体吃饱（饥饿 < 0.05）即离席，不独食到光。

实测 4 分钟（青蛙静止）：单饵同时进食恒为 1（超员 0.0%）；等位盘旋中位 0.5 秒、
最长 ~4 秒（都是换座位的过渡，不是死等）；没有出现 >8 秒的"绕食不吃"僵局。

姿态与步态覆盖四种果蝇状态：飞行（22 Hz 振翅，翅尖上下划弧、翅面左右扫掠，六足向后收拢）、
行走（三角步态，摆动相抬脚、步频 ∝ 速度）、进食（口器伸向食饵、前足搓动）、
梳洗（前足举到**头部轮廓之上**在复眼上大圈擦洗 1.6 s、身体后仰、翅膀轻颤；
每 2.5~5 s 一次，占全部果蝇-帧的 13%，即真实果蝇的清洁行为）。翅膀的展开度随高度连续插值，
因此起飞展开、落地收拢的过程是平滑的，不会在状态切换时突然跳变。

## 5 · 真·果蝇：FlyGym / NeuroMechFly 流水线

[`real_fly_demo.py`](real_fly_demo.py) 通过 FlyGym 2.x 的组装式 API 构建 EPFL 的
[NeuroMechFly](https://neuromechfly.org) 并离屏渲染——本文最上方两张图就是它的输出。

| 阶段 | API 调用 | 结果 |
|---|---|---|
| 身体 | `NeuroMechFly()` + `colorize(visuals.yaml)` | 70 个 micro-CT 体节，应用材质 |
| 关节 | `Skeleton(AxisOrder.PITCH_YAW_ROLL, JointPreset.ALL_BIOLOGICAL)` + `add_joints()` | 126 个转动自由度，逐关节刚度/阻尼/armature |
| 驱动 | `add_actuators(..., ActuatorType.POSITION)` | 126 个位置执行器（肌肉代理） |
| 附着 | `add_leg_adhesion()` | 6 个 tarsus5 附着执行器，`ctrl ∈ [0,1]` |
| 视觉 | `add_vision()` | 2 个复眼相机 → `get_raw_vision()` 与 `get_ommatidia_readouts()` |
| 物理 | `FlatGroundWorld` / `BlocksTerrainWorld` + `Simulation` | MuJoCo 3.9，1 ms 步长 |

暴露给控制器的接口（即神经环路可读写的通道）：

| 方向 | 通道 | 分辨率 |
|---|---|---|
| 感觉 | 视觉 | 2 × 721 个小眼，黄型/淡型分离，单眼视场角 157°，含鱼眼模型 |
| 感觉 | 本体感觉 | 全部 126 个自由度的关节角与角速度 |

## 9 · 已知限制

- **界面文案为中文**。字体依次在 macOS 系统字体与 `pygame.font.match_font` 中解析；
  在 Windows / Linux 上请把中文字体 `.ttf` 加入 `FONT_PATHS`（`main.py:39`）。
- **音效为尽力而为**：由 numpy 合成后经 `pygame.sndarray` 播放，无音频设备时静音运行。
- **游戏智能体是行为模型，不是生物物理模型**：4 个手工整定的 LIF 环路，为可读性与交互
  延迟取舍。科学模型见 [§5](#5--真果蝇flygym--neuromechfly-流水线)。
- **FlyGym 2.1.0 的传感器命名缺陷**：逐腿接地传感器引用了不存在的元素名，因此
  `real_fly_demo.py` 以 `add_ground_contact_sensors=False` 组装；接触力仍可通过
  `get_bodysegment_contact_forces()` 获取。属上游问题。
- 已在 macOS 验证（Python 3.14 + pygame-ce 2.5.8；FlyGym 2.1.0 / MuJoCo 3.9 跑在
  Python 3.12 上），其余平台未测试。
